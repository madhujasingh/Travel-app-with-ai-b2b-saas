----------------------------------------------------------------------
BOOKING-DETAILS API (p.30-40)
----------------------------------------------------------------------
Purpose: Retrieves the details of a completed insurance booking using
the bookingId returned after a successful booking.

Method: POST
API: /oms/v1/insurance/booking-details

Sample Request Payload:
{ "bookingId": "{{insBookingId}}" }

Request Parameter Verbose:
  bid - Booking Id: unique id (the unique insurance booking reference
        ID received from the Insurance Booking API response).

Booking Details API Response Verbose (p.38-40):
  order
    Booking Id     - unique id received
    "amount"       - TripSafe Insurance Amount
    "markup"       - Agent markup if any
    "Delivery info"- Agent Info
      email          - email id of traveller
      Contact        - traveller contact num.
    status
    "createdOn"    - Booking creation time
  "itemInfos"
    INSURANCE
      iinfo - insurance information
        plid - plan id taken from Search Resp
        "pi" - Product info
          "pid" - Product Id, taken w.r.t. Plan Id from search resp
          pn    - Product name
          Ip    - Insurance Provider Name (e.g. ABHI)
          aps   - List of Assistance Provider (AAI, BOXX)
          rname - Region name
          pbft  - Product benefits information
            bv    - Visibility of the benefit (ON_BANNER, ON_COMPARE)
            name  - Benefit name
            type  - Benefit type (ASSISTANCE, INSURER)
            bfp   - benefit provider
            dsc   - description if any
          iti - Insurance Traveller Info
            Id    - traveller no.
            Dob   - Date of birth (YYYY-MM-DD)
            Age   - age of the traveller
            Fn    - first name of the traveller
            Ln    - last name of the traveller
            Isio  - insurance opted (optional)
            Eid   - Email ID of the traveller
            Pnum  - Passport number of the traveller
            Gen   - Gender of Traveller
            Ni    - Nominee information
              "nn"  - Name of the nominee
            Ifc - Insurance fare component
              SPGST, AC, SP, TF, ACTDS, NF (same field set as Search/Review)
          "policyId" - Unique Travel Policy Id generated PER TRAVELLER
            (i.e. one policyId per traveller, not one per booking - a
            multi-traveller booking has multiple policyIds, one inside
            each iti[] entry, as shown in the sample above.)
  *** isq & iti are repeated again in the response and CAN BE IGNORED ***
      (per the doc's own explicit note - i.e. the isq/iti block sibling
      to iinfo at the itemInfos.INSURANCE level is a redundant echo,
      not new information - the authoritative traveller/policy data is
      inside iinfo.pli[].pi[].iti[] instead.)

BOOKING-DETAILS API-FAQs (p.41):
  Q: Is this API idempotent? Can it be safely called multiple times?
  A: API is NOT idempotent; each hit returns a unique response. Yes, it
     CAN safely be called multiple times (i.e. no side effects from
     repeated calls, just don't expect byte-identical responses).

  Q: What fields are guaranteed in the response regardless of provider
     (e.g. bookingId, amount, status)?
  A: Email ID, contact number, gender, policyId.
     (NOTE: this answer doesn't actually list bookingId/amount/status
     despite the question naming them - likely means those ARE also
     guaranteed as "obviously always present" and this FAQ is only
     calling out the less-obvious ones. Don't read this as "bookingId
     might be absent.")

  Q: Are optional fields like additionalInfo, fd.ifc, and iti.policyId
     always returned even if empty or zeroed?
  A: No - they are never empty (i.e. these fields are always populated
     with real values, never returned as blank/zero placeholders).

  Q: Does the response provide a history of status changes (e.g.
     CREATED, SUCCESS), or only the final status?
  A: Response includes BOTH status history and final status.

  Q: Can a booking be retrieved using alternate identifiers like
     policyId, email, or passport number?
  A: Bookings can currently be retrieved ONLY via booking ID in the
     API. Policy ID can be used in "Manage Cart" via the TripJack
     Portal (not via API).
