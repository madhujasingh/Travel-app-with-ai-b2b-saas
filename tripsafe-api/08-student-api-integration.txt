----------------------------------------------------------------------
STUDENT API INTEGRATION (p.66-83+)
----------------------------------------------------------------------
New Travel Insurance plans specifically for students travelling abroad
for education over a LONGER duration than standard TripSafe plans.

3 new plans:
  - TripSafe Student Gold      ($100,000 Cover)
  - TripSafe Student Platinum  ($250,000 Cover)
  - TripSafe Student Titanium  ($500,000 Cover)

To make a Search request a student-plan search, add:
  "ict": "STUDENT"  // insurance channel type
  "cd":  "180"      // coverage duration (comment in doc's own sample
                     // lists valid values as 30,60,90,180,360,730,1095
                     // - but see the "Important Note" below, which
                     // only documents 4 of those 7 for Student
                     // specifically; the other 3 (30/60/90/360) might
                     // be valid for a DIFFERENT channel type reusing
                     // this same "cd" field, e.g. AMT - confirm live,
                     // don't assume all 7 work for ict=STUDENT.)

Important Note:
  - Eligible Age Group: 18 to 45 years ONLY.
  - Available Coverage Durations for Student (values to fill in "cd"):
      6 Months -> 180
      1 Year   -> 365
      2 Years  -> 730
      3 Years  -> 1095

APIs Included:
  - Search API - Student plan search functionality (new)
  - Review API - SAME as existing implementation; no changes required
  - Book API   - Student plan booking functionality (new fields, see below)

Student Search API - Sample Request Payload:
{
  "isq": {
    "sd": "2025-12-26",
    "cd": "180",
    "isc": { "iri": [ { "rkey": "US", "rt": "COUNTRY" } ] },
    "iti": [ { "age": 20 }, { "age": 29 } ],
    "ict": "STUDENT"  // Insurance Channel type
  }
}
(No "ed" in the request - TripSafe computes the end date from sd+cd
server-side; confirmed because the RESPONSE's echoed-back isq DOES
include a computed "ed", see full response below.)

Student Search Request Verbose (p.67-68, isc detail continues on p.74):
  sd  - Start date of insurance coverage (YYYY-MM-DD)
  cd  - Coverage Duration
  isc - Insurance search criteria, includes region info
    iri[]
      rkey - Name of Country opted to study (e.g. France, Australia,
             Canada, Europe, Asia) [p.68's own table mislabels this
             column "rn" instead of "rkey" - a labeling slip, since
             every real sample payload for Student (and everywhere
             else in this doc) uses "rkey"; p.74's version of this same
             table correctly says "rkey" - trust the samples/p.74 over
             p.68's "rn".]
      rt   - Type of region (e.g. "Country", "POPULARREGION")
    pisc - Product insurance search criteria (same rkey/rt shape)
    iti[] - list of travellers (age only, for Search)
  "ict" - Insurance channel type ("ict": "STUDENT")

NOTE (p.69): the following fields MAY appear in the Search API response
but are NON-FUNCTIONAL for the student flow and should be IGNORED:
  isef, pci, adr
(This doesn't contradict the "isef = is embedded flow" guess from
Section B above - it just means isef is irrelevant specifically when
ict=STUDENT, since Student isn't the Embedded flow.)

Student Search Result Verbose (p.73-77):
  sd/ed - start/end date (YYYY-MM-DD)
  isc.iri[].rkey/rt, isc.pisc.iri[].rkey/rt, isc.iti[].age - as above
  "ict" - Insurance channel type
  "searchId" - unique search id
  "isr" - Insurance search result
    iinfo.pli[].plid, .pi (product info: pid, pn, pi/productIdentifier,
    Ip, aps, rname, pbft)
    Pfd - Product fare details: Ppd (per-day price per age), Ppdf (day
          number -> age-wise fare component), Ifc (fare component)
    pbft -> bv, name, type, bfp, dsc
    Ifc -> this table only lists AC/TF/ACTDS/NF (fewer than the 12-field
           set seen in real samples elsewhere, including THIS SAME
           section's own real response above, which also shows
           APGST/SPGST) - treat this table as an abbreviated/incomplete
           list, not authoritative on which Ifc fields actually exist.
    "The below keys may vary in value according to plan opted (Gold,
    Silver, Platinum etc)" - CONFIRMS the meaning of 3 previously-
    unexplained boolean flags (resolves earlier open question #10):
      "ibrbf" - true/false - "Is BRB free" (BRB = Blue Ribbon Bags, the
                baggage-tracking assistance provider seen elsewhere as
                "bfp": "BRB_STD" and the "optedAddons.brbServiceNumber"
                field in standalone bookings)
      "iesf"  - true/false - "Is eSIM free"
      "iboxf" - true/false - "Is BOXX free" (BOXX = one of the two core
                assistance providers seen throughout, alongside AAI)
      "comm"  - Commission (numeric)
    "ptf" - Plan total fare
